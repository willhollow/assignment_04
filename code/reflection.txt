What I learned

The main idea was lineage: each pipeline step only adds columns. It never drops,
renames, or overwrites one, so every number in the final table can be traced back to
the raw data. Each function follows copy-add-return: copy the input, add one new
column, return the copy. The code tests read the source with ast and flag any call to
.rename() or .drop(), even in code that never runs. I had an unreachable second
`return payroll.rename(...)` in payroll_export, and it failed the test. The fix was to
build the export as a NEW DataFrame from the columns I needed.

I also learned when to use each kind of apply. Series.apply runs an element function
(parse_hours, clean_currency) on one column. A row apply, DataFrame.apply(..., axis=1),
is needed when a function uses two values from the same row, like calc_gross_pay with
hours and rate.

The left merge keeps one row per timesheet row (the grain). An employee_id that is not
on the roster gets NaN for hourly_rate_usd instead of disappearing. That NaN then
drives everything after it: calc_gross_pay returns 0.0, classify_pay checks
"unmatched" before overtime, the export skips those rows, and the app shows a warning
naming the employee_ids.

Where I struggled

1. In build_payroll I wrote `payroll = add_hourly_rate(employees)`, which replaced the
   cleaned timesheet with the roster. It looked fine at a glance, and the code test did
   not catch it. Only the pipeline tests did. The right line is
   `employees = add_hourly_rate(employees)`. Next time I will check that each
   assignment targets the frame I just changed, and I will run the whole test suite,
   not just one test.

2. I am not sure when pandas gives a copy and when it gives a view of a boolean-indexed
   slice. I used .copy() to be safe. To fix this, I will read the pandas docs on views
   vs copies and try changing a slice to see if the original changes.

3. The app has to show exact values like "241.75" and "$4,133.72". I used f-strings
   with :,.2f. Totals are .sum() on a Series and counts are len() of a boolean-indexed
   frame, so the app does no row math. That stays in the package.
